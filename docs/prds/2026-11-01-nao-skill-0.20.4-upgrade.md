## 四、用户场景

- **维护者**：clone 后 `pi install -l --approve` 直接物化 0.20.4，不读到「当前 0.12.0」这类过期事实。
- **PM / RD / QA**：开新会话即载入 0.20.x 角色卡（codegraph 定位、一任务一 PR、按仓归属回收），不再吃 0.13.0 的旧纪律。

## 五、业务规则

1. **pin 为唯一事实来源**：不把机制资产复制回仓（`.agents/` 仅保留 shim + 自有 skills/commands）。
2. **不放宽 `devEngines`**：若 `pi install` 撞 `EBADDEVENGINES`，改用仓外方式执行，**不得**改 `package.json` 的 `devEngines`。
3. **失败即回滚**：pin 单点可 `git revert` 回 0.13.0，无数据迁移。
