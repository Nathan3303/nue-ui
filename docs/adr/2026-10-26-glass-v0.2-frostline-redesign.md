# ADR：Glass 主题 v0.2 采用 Frostline 设计语言（放弃 Apple HIG 临摹）

- 状态：**已接受**（2026-10-26，随 `nue-ui-theme-glass@0.2.1` 发布）
- 关联：Issue [#81](https://github.com/Nathan3303/nue-ui/issues/81) · PR [#82](https://github.com/Nathan3303/nue-ui/pull/82) · 设计文档 `docs/prds/2026-10-25-glass-v0.2-frostline.md`

## 背景

v0.1.0 的 glass 本质是「shadlike 换皮」：34 个组件样式文件 90% 结构照抄，只替换了值。色板用 Apple 系统蓝 `hsl(211 90%)`，玻璃 `saturate(180%)` 把背景色放大成糖水。

两条独立的证据说明这不够：

1. **设计上**：`Apple HIG 玻璃拟态` 本身已被大量产品模仿到近乎模板；同时命中 frontend-design skill 列出的「AI 生成痕迹」清单（SaaS 卡片套件：磨砂白卡 + 大圆角 + 柔和阴影 + 彩色渐变）。客观上读起来是临摹品，不是有自己观点的设计。
2. **工程上**：v0.1 收敛后仍有 4 个只有人眼能发现的缺陷（输入框边框 1.33:1、textarea placeholder 2.31:1、destructive 文字 3.52:1、玻璃裁剪），说明「照抄结构改值」这条路无法产生对自身一致性的理解。

## 决策

**放弃「复制 shadlike 改值」，改为「先定设计系统，再让组件从系统派生」。视觉语言重定义为 Frostline（霜线）。**

题材与隐喻（决定一切下游选择）：

- 题材：**开发工具 / 技术产品的落地页**；受众：工程师；任务：让人相信这东西精确、可靠、不花哨
- 隐喻：**结霜的光学玻璃 + 阳极氧化金属面板**——不是果冻，是仪器

推论出的三条硬规则：

| 规则                 | 表现                                                                                     |
| -------------------- | ---------------------------------------------------------------------------------------- |
| 层次用**线**不用影   | 1px 结构性描边 + 内高光；阴影收缩到单层 `0 1px 2px`                                      |
| 玻璃是**霜**不是糖水 | 色相 192 / 主色饱和 38%（v0.1 是 211 / 90%）；`blur(16px) saturate(118%)`；α 0.82 / 0.86 |
| 颜色纪律             | 圆角 6px；Ember 是唯一用于**强调/装饰**的暖色（状态色不受此限）                          |

唯一的记忆点集中在**霜边**（外冷线 + 内白线），其余一律安静：无渐变装饰、无彩色光晕、无入场动画。

## 对照过的备选模式（含不采纳理由）

| 备选                                                   | 不采纳理由                                                                                                                                          |
| ------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| **B. 琥珀光 Amberglass**（暖琥珀、光学玻璃、黄铜镶边） | 暖色玻璃在暗色模式下极难同时满足「琥珀身份」与 AA 对比（实测 `hsl(30 68% 38%)` 作文本落在玻璃上仅 3.09）；且温暖质感与「精密仪器」题材相悖          |
| **C. 墨玉 Obsidian**（近黑墨玉、锐利高光、戏剧对比）   | 无彩色会丢掉品牌识别；且偏执于深色画面，不适合以亮色为主的文档站与落地页                                                                            |
| **D. 继续微调 v0.1**（保留 Apple HIG 结构，只改数值）  | 换皮改不出观点；`saturate(180%)` 是果冻感的直接来源，不换掉这套参数就无法摆脱临摹气质                                                               |
| **E. 主题包打包 Web Font**                             | 会给每个消费方加 75 KB 字体负担，且与「组件库主题应零额外资源」的既有约束冲突。改为**推荐自托管 IBM Plex**（README 给代码），主题包本身仍交付系统栈 |
| **F. 引入 `overflow: clip` + `clip-margin` 解决裁剪**  | Safari 完全不支持（WebKit bug 236153），且只解决容器裁剪、对 `backdrop-filter` 纹理边界无效                                                         |

## 后果

**正面**

- 首次有一套可执行的、有观点的视觉语言，且**机械可验证**：687 例测试 / 254 组对比度配对 / A1–A11 + S1–S8，全带防假绿自证
- 重写过程本身暴露了 3 个 v0.1 遗留的真缺陷（`switch` 滑块 1.16:1、`scroll-bar` 拇指 2.25:1、同名 token 在不同容器里对比度不同），证明「派生」比「照抄」更能发现问题
- 对比度余量从「贴 4.5 的线」改善到 **4.738（余量 0.238）**

**负面（必须一起记住）**

- **低饱和压缩了可用对比带**：暗色深文本档只能是两级（≈secondary / 800+），不是实现缺陷而是这套色板的必然代价
- **破坏性升级**：色板/圆角/密度/玻璃参数/字重全变，v0.1 的变量覆盖定制会失效或错位（README 与 release notes 均写明「对照表重算，不要逐个打补丁」）
- **`dist/global/variables.css` 9,971 B / 上限 12,000**：设计系统 token 更多，余量已不多，下次新增全局 token 前需先考虑拆文件

## 不要回退（写给未来的自己）

**如果觉得 Frostline「太素」，先读这份 ADR，不要直接调回高饱和 + 大圆角 + 多层阴影。**

那套参数不是「更有设计感」，而是 2024–2026 年间 AI 生成界面与 Apple 衍生产品的默认组合——它在视觉上看似安全，实际上让产品彻底失去辨识度。

真要提亮，正确方向是**在霜边或排版上做加法**（例如更大的字号对比、更明确的等宽数据标记），而不是放开饱和度与圆角。
