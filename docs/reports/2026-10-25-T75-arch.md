## 三、决策点 1：tokens 体系 —— **复用 shadlike 的 hue + HSL 阶梯 + `--nue-dark-switch`（采纳 A），但按玻璃语义重写映射值**

### 3.1 模式对照（⓪ 必做，含不采纳理由）

| 候选                                                                          | 机制                     | 适用条件                                       | 结论                                                                                                                                                                                                                                                                      |
| ----------------------------------------------------------------------------- | ------------------------ | ---------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **A. 复用 shadlike 阶梯**（hue + `--nue-hsl-sN/lN/oN` + `--nue-dark-switch`） | 单套声明，数值随开关翻转 | 需要「一个开关切整套」且必须单点退化           | **采纳**                                                                                                                                                                                                                                                                  |
| B. glass 自建两套静态色阶（亮块 + 暗块）                                      | 两套字面值分别生效       | 需要媒体查询、属性选择器或 `light-dark()` 触发 | **不可行**：CSS 没有「以数值自定义属性为条件切换整块声明」的语法。R3 禁止 media query，剩余路径只有属性选择器（需 JS/标记）或 `light-dark()`（需 `color-scheme`，即第二套开关机制，R3 明确禁止）。强行实现只能把每条声明写成两份 calc 或用重复规则，等价于 A 的更差实现。 |
| C. `light-dark()` + `color-scheme`                                            | 浏览器原生双模           | 可以接受 `color-scheme` 作为唯一开关           | **不采纳**：与 `--nue-dark-switch` 形成双机制（R3/N5 禁止），且消费方切暗要改两处。                                                                                                                                                                                       |
| D. 独立命名空间（`--nue-glass-token-*` 全套）                                 | 与 shadlike 解耦         | 允许破坏变量契约                               | **不采纳**：直接违反 AC-12/R1。                                                                                                                                                                                                                                           |

> 结论 A 不是偏好，是 R3 + AC-12 的**唯一可行解**：要让 9 个浮层 + 25 个实底在 `--nue-dark-switch` 0/1 下整体翻转，且 glass ⊇ shadlike 变量名，只能用共享阶梯 + 同名语义层。

### 3.2 采纳方案：三层 token + 四条硬规则

| 层     | 内容                                                                                                                                                                                                     | 约束                                                                                                                                                    |
| ------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| P 原语 | `--nue-brand-hue: 211`、`--nue-success/warning/error-hue: 120/30/10`；`--nue-hsl-s0..s100`、`--nue-hsl-l0..l100`、`--nue-hsl-o*`；`--nue-dark-switch`、`--nue-dark-prefix`                               | 阶梯公式**逐字复用** shadlike（保证同名同构）。`--nue-dark-prefix` 改写为 `calc(var(--nue-dark-switch) * 2 - 1)`（取值同为 -1/+1，去掉 `cos()` 依赖）。 |
| S 语义 | `--nue-primary-color-0..1000`、`--nue-success/warning/error-color-*`、`--nue-*-text-color`、`--nue-border-color`、`--nue-divider-color`、`--nue-link-color`、`--nue-*-shadow-color`、排版/间距/圆角/动画 | **名字与 shadlike 完全一致**；值重算（见 3.3）。                                                                                                        |
| C 组件 | 34 个文件内的 `--nue-<comp>-*` 局部变量                                                                                                                                                                  | 文件/选择器/局部变量名**照 shadlike 复制后只改映射值**；不允许 RCS、不允许硬编码模糊值。                                                                |

**四条硬规则（写入 README，作为 review 判据）**

1. **RCS 只允许出现在 `src/global/variables.css`，且 glass 取 0 处**：颜色一律 `hsl(h, s, l[, a])`（legacy 4 参数 + `calc()` alpha），派生一律换阶梯步进，不用 `from … h s l`。
2. **禁用 `cos()/sin()/tan()`**：`--nue-dark-prefix` 用 `switch * 2 - 1`。
3. **新增变量只允许 `--nue-glass-*` 前缀**（AC-10），共 6 个（3.3.3）。
4. **组件层只做映射**：`backdrop-filter` 的值必须是 `var(--nue-glass-blur)` 字面量，`background-color` 必须是 `var(--nue-glass-bg)` 或 `var(--nue-glass-solid)`。

> 规则 1 的收益是可度量的：AC-16 从「依赖 Baseline 2024-09 的 RCS」降级为「只依赖 ES5 时代的 `hsl()` + `calc()`」，RK-6 的「必要时保留静态色阶回退」不再需要（回退内建）。

### 3.3 token 数值（rd-fe 照此实现，qa 照此断言；对比度为脚本实算值）

#### 3.3.1 语义色映射（翻转 vs 固定）

> **饱和度口径（D11）**：primary 色阶的饱和度**锁定字面值**（500/700/800/900/1000 = `90%`，600 = `95%`），**不用 `--nue-hsl-s90`**。原因：阶梯 s90 在暗色降为 80%，会把 700 暗阶从 l70/s90 变成 l70/s80，值级偏离本表；玻璃主题的品牌饱和度不应随明度翻转衰减。语义色（success/warning/error）仍走阶梯 s70/s80（与 shadlike 同构）。
>
> **实测复核（2026-10-25，用交付后的 `variables.css` 复算）**：白字对 `primary-600` = **5.82 / 4.82**；语义实心填充 `hsl(120,70%,30%)` / `hsl(30,80%,32%)` / `hsl(10,80%,40%)` = **4.95 / 6.10 / 6.08**（两模式同值）；功能性边框对玻璃最坏 **3.39 / 4.28**；主文本 **7.24 / 5.87**。与 rd-fe 自算逐值一致（唯一分歧：`--nue-link-color` 700 暗阶我算 4.41、rd-fe 报 4.39，结论相同——均 <4.5，已由 D11 替换）。

### 3.4 AC-12 的口径与测试实现（可直接照写）

- **口径（双门禁，PM 2026-10-25 裁定 B + 增量补充）**：
    - **主门禁（契约，批 1 即可绿）**：`global/variables.css` 定义名 ⊇ shadlike 同文件 **143** 名，加 glass 新增 **6** 名 → **149**；新增名全部匹配 `^--nue-glass-`。
    - **组件层门禁（增量，不阻塞分批）**：对**已存在**的每个组件文件断言
      `defined(glass:file) ⊆ defined(shadlike:同文件) ∪ {名字匹配 ^--nue-glass-*}`，并叠 M4（`referenced(glass) − defined(glass) = 0`）。批 1 时只对 9 个浮层文件生效，批 2 自动扩到 34 个文件 / 276 个局部名，无需改断言。
    - **glass 前缀例外的约束（关键，不得省）**：组件文件里出现的 `--nue-glass-*` **必须已在 `global/variables.css` 的 6 个基元之内**（即只能是「覆盖」不能是「发明」）。不删，等于给「自造玻璃数值」开后门，并会弱化 §四 A9 的嵌套覆盖证明。
- **为何允许集要加 glass 前缀**：§四 A9 强制 4 条嵌套覆盖规则，它们必须写在组件文件里（`.nue-dialog { --nue-glass-blur: none }`）；纯 `⊆` 会把**本方案自己要求的写法**判红。→ 采纳 PM 的允许集；但加上述约束封住「发明新 glass 名」的漏洞。最终效果：改名/发明非 glass 名 → 红；合法局部覆盖/glass 基元覆盖 → 绿。
- **为何不只做全局 143**：组件层 **276** 个局部名（`--nue-button-lo`、`--nue-message-node-inner-*` 之类）如果被改名，组件仍能渲染（M4 不报），但会破坏「与 shadlike 逐文件可 diff」（§六 可维护性 NFR）与后续同步。`⊆` 同时捕捉**改名**（新名不在 shadlike 同文件集合内）与**新增**，允许无害的删除。
- **另一条更强、必须一起加**：`referenced(glass) − defined(glass) = 0`（M4）。shadlike 现状 2 个悬空（`--nue-hsl-90`、`--nue-text-font-style`），glass 不得继承。
- **解析器规格**（test helper，约 120 行，独立文件 `packages/themes/glass/__tests__/css-tokens.ts`）：
    - 支持 `var()` 链解析、`hsl(h, s, l[, a])` 四参数、`calc(A% ± var(--nue-dark-switch) * B%)`、`calc(var(--nue-dark-switch) * 2 - 1)`、纯数字/百分比；
    - **不支持**也不需要 RCS（因为规则 1 禁止），遇到 `from` 直接 fail —— 解析器能力与实现约束互为看守；
    - 对比度沿用 shadlike `__tests__/contrast.test.ts` 的 WCAG 公式（`relativeLuminance` / `contrastRatio` 逐字复制，**不抽公共包**：抽包要改 shadlike 测试文件，越 N3 边界）。

### 3.5 结论（Q1）

复用 shadlike 的 hue + HSL 阶梯 + `--nue-dark-switch`；**不自建静态双套**（R3 下不可实现）。差异只有三处：① primary 阶梯恢复饱和度（shadlike 全 s0 是灰色）② 语义填充固定不翻转 ③ 玻璃 6 个基元。AC-12 用「全局 143+6 主门禁 + 组件层 per-file ⊆ + 引用 0 悬空」守住（§3.4）。

### 4.4 ⚠️ 新发现（RK-7）：overlay 的 `opacity` 动画会「吃掉」子浮层的模糊

| 方案 | 做法                                                                                                                                                                      | 结论                                                                                    |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| 采纳 | glass 自己的 `overlay.css` 用 `--nue-overlay-animation-name: glass-scrim-in`，关键帧只动 `background-color` 的 alpha（透明 → `--nue-glass-scrim`），**始终 `opacity: 1`** | 采纳：改动只在 glass 的 CSS 内，零 SFC 改动；成本 = 全屏纯色重绘（无 blur 采样），240ms |
| 否   | 保留 `opacity` 动画，接受模糊「闪现」                                                                                                                                     | 直接损害 AC-05 的「背景可透出」观感                                                     |

### 5.2 退化实现（单点，两路径同构）

```css
/* src/global/variables.css 尾部（顺序即语义：必须在基值之后） */
@supports not (backdrop-filter: blur(1px)) {
    :root {
        --nue-glass-blur: none;
        --nue-glass-bg: var(--nue-glass-solid);
        --nue-glass-border: var(--nue-border-color);
    }
}
@media (prefers-reduced-transparency: reduce) {
    :root {
        /* 同上 3 条，逐字相同 */
    }
}
@media (prefers-contrast: more) {
    :root {
        /* 同上 3 条，逐字相同（D4 采纳；覆盖不支持 reduced-transparency 的 Safari/Firefox） */
    }
}
```

- **只判无前缀**：`@supports not (backdrop-filter: blur(1px))` 保持 PRD R6 原样。理由：若写成 `not ((backdrop-filter:…) or (-webkit-backdrop-filter:…))`，则 Safari ≤17 会走「支持」分支，而 autoprefixer 是否产出 `-webkit-` 取决于 browserslist（本仓未配置 `browserslist`），会出现「判定支持但实际无模糊」的半吊子态。单一判据 + 目标浏览器（Safari 18+）已支持无前缀 = 分支一致。
- **退化只改 3 个变量**，因为 §三 规则 4 强制所有组件只引用这 3 个变量的字面量 → **单点覆写即全局生效**，这也是能被静态证明的关键。

**覆盖边界（必须写进报告给 PM，不许含糊）**：以上证明的是「退化规则存在、且覆盖了全部模糊入口、且退化后配色达标」，**不是**「浏览器确实按此渲染」。浏览器级验证需 Playwright/视觉回归，PRD N7 已排除 → 留给 PM 人工走查（M6）。jsdom 下尝试 `matchMedia('(prefers-reduced-transparency: reduce)')` 只会得到 `false`，不具备证明力，不要写这种假断言。

### 5.4 结论（Q3）

三条路径各 1 块、每块 3 条覆写（合计 9 条），总开关是 `--nue-glass-blur/BG`；用 A1–A11 共 11 条静态断言（含退化态对比度实算）证明。**不新增浏览器测试工具链**（NFR「不新增构建工具链」）。`prefers-reduced-transparency` 只覆盖 Chromium，故 D4 已采纳第三条 `prefers-contrast: more` → PRD AC-17。

**问题**：`hsl(from …)` 的最低浏览器版本是否与 AC-16「主流现代浏览器最近 2 个版本」一致？

**答**：一致，且**不必依赖**。

| 项                            | 数据                                                                                                                                                                                                                                                                                                                              |
| ----------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| RCS Baseline                  | Newly available **2024-09-16**；Chrome 125 / Edge 125 / Safari 18 / Firefox 128                                                                                                                                                                                                                                                   |
