# nue-ui v1.15.2 — date-only 值的时刻口径统一

> **这是一个可见行为变更版本（非 breaking）。** 若你的代码依赖「date-only 值自动补当前时刻」，升级后需要自行补时刻；其余用法无需改动。

## 改了什么

`type="datetime"` 且 `modelValue` 是 date-only 串（`YYYY-MM-DD`）时，**触发器与面板原本显示两个不同的时刻**：

| 位置           | 1.15.1       | **1.15.2**  |
| -------------- | ------------ | ----------- |
| 触发器         | `00:00`      | `00:00`     |
| 面板时间选择器 | **当前时刻** | **`00:00`** |

同一个值在两处不一致，根因是两条路径对「date-only 该补什么时刻」的口径不同：触发器走 `parseDate`（本地午夜），面板走 `parseDateTime` 的兜底（取 `now` 的时分）。

## 口径

**date-only 本身不含时刻信息 ⇒ 统一按 `00:00` 解释，不臆测。**

## 不受影响

| 输入示例                | 行为                             |
| ----------------------- | -------------------------------- |
| `2024-05-06T08:09:00`   | 仍按值里的时分回填（T 形式）     |
| `2024-05-06 08:09`      | 仍按值里的时分回填（空格形式）   |
| `2024-05-06 12`（缺分） | 缺的那一段仍回退当前时刻         |
| `type="date"` 录入      | 时间部分固定 `00:00`，与之前一致 |

## 升级会感知到什么

1. **打开面板**：date-only 值的时间选择器从「当前时刻」变为 `00:00`（与触发器一致）。
2. **只改日期**：date-only 回填状态下只点日期、不动时间，`update:modelValue` / `change` 出来的值时刻为 `00:00`，不再混入当前时分。
3. **无效值回填**：`modelValue` 无法解析时，面板时分同样归零（原为当前时刻）；年 / 月的兜底逻辑不变。

## 升级建议

唯一需要的迁移动作：**若你在消费方依赖「date-only → 自动补当前时刻」来构造带时刻的值**，请在拿到值后自行补时刻。其余场景无需改动。

```js
// 升级前：值里可能混入「打开面板那一刻」的时分
// 升级后：date-only 一律 00:00 —— 需要当日当前时刻就自己补
const value = dateOnlyInput ? `${dateOnlyInput}T${currentTime}` : emitted;
```
