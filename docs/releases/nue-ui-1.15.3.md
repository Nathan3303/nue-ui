# v1.15.3

**这一版只做修复，没有破坏性变更**：路由链接终于能被键盘和读屏软件正常识别，头像加载失败后不再「永久卡死」，开关旁写文案也不用再绕路。

## 🐛 修好了

### 用「路由」做的链接，现在真的是一条链接

以前用路由属性做跳转时，页面上那个链接**没有地址**：鼠标点还能跳，但**键盘 Tab 走不到它、不能在新标签页打开、读屏软件也不说它是链接**——看起来正常，其实只有一半功能。

现在它是真正的链接：能 Tab 聚焦、回车激活、右键「在新标签页打开」。顺带修掉了一个小毛病——用对象形式传目标时，它会把 `[object Object]` 当作属性写进页面里。

### 头像加载失败后，换新地址就能恢复

以前头像图片一旦加载失败（网络断了、登录过期、地址 404），**这个头像就再也不显示了**，即使换成可用的新图片地址也一样，只能刷新页面或换页面才恢复。列表里复用头像时更糟：一条坏图会连累后面所有头像。

现在只要图片地址真的换了，就会重新尝试加载并显示。同一个坏地址不会反复重试（避免图片闪动）。

### 开关组件可以直接写文案了

以前 `<nue-switch>开启通知</nue-switch>` 里的文字会被**悄悄丢掉**，必须换一套写法（`show-text` 加具名插槽）才出文案——和按钮、复选框的直觉写法不一致，踩中的人第一反应是「样式坏了」。

现在默认插槽就是开关文案，跟其它组件一致；空白内容也不会留下空占位。开关的无障碍行为和样式没有任何改动。

## ⚠️ 请留意

- **优先级口径订正**：`href` 与路由属性同时传入时，**以 `href` 为准**。旧文档写的是「路由优先」，与实际行为相反，本次一并订正了文档与示例说明。若你的代码同时传了两者并且依赖了旧文档的说法，请只保留一个。
- 如果你之前为了出开关文案写了 `show-text` 加具名插槽的绕行写法，**可以保留也可以简化**成默认插槽，两种写法都支持。
- 头像的「取名字首字母」回退一直是**不可用**状态（不是本版引入），本版没有改它，已单独记录待办。
